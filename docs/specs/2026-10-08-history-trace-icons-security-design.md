# History View, Flow Tracing, Collapse Persistence, VS Code Icons, Security Hardening, Merge Finder

Design for six additions to the `mygit` extension. Each section states the behaviour, the components touched and the constraints behind them. Section order matches the implementation order in Section 8.

---

## 1. Scope

| Item | Summary |
| --- | --- |
| Collapse persistence | Left Panel collapsed/expanded state stored per repository. |
| Security hardening | Option-injection guards, bounded git output, askpass over authenticated IPC, secret redaction, payload validation, hardened file writes, strict CSP, workspace-trust declaration. |
| Codicons | VS Code codicon font replaces the hand-drawn SVG icon set. |
| File icons | File and folder icons resolved from the active VS Code file icon theme. |
| Flow tracing | Highlight ancestors, descendants or both of a commit in the graph. |
| History view | Filtered, paginated commit list in the centre pane, with a compare mode. |
| Merge finder | "When was A merged into B": merge commits on B that brought in A's commits. |

Out of scope: graph lanes in the History view, squash-merge detection by patch content, icon theme `extends` chains (VS Code icon themes have none), localization.

## 2. Collapse persistence

### 2.1 Behaviour

- Collapsed state of Left Panel sections, local branch folders, remote nodes, remote branch folders and tag folders persists per repository across tab close and VS Code restart.
- A maximised section remains session state (webview state only).
- A filter query still forces matching folders open without changing the stored state.

### 2.2 Data

- `RepoPrefs.collapsed: string[]`: keys of collapsed nodes, same key scheme as the current `leftCollapsed` record (section ids, folder keys, remote keys). Absent keys are expanded.
- `DEFAULT_REPO_PREFS.collapsed = []`.
- New op `prefs:collapsed { collapsed: string[] }` → `store.setRepoPrefs({ collapsed })` (`workspaceState`, key `mygit.repoPrefs`).

### 2.3 Migration

On first render, if `repoPrefs.collapsed` is empty and webview state holds a non-empty `leftCollapsed`, the webview sends `prefs:collapsed` with its keys and removes `leftCollapsed` from webview state.

### 2.4 Components

- `src/panel/messages.ts`: `RepoPrefs`, `DEFAULT_REPO_PREFS`, `Ops`, `OP_NAMES`.
- `src/panel/operations.ts`: op handler.
- `src/webview/columns/LeftPanel.tsx`: replace `usePersisted('leftCollapsed')` with a set derived from `state.repoPrefs.collapsed`; toggles send `prefs:collapsed`. Local optimistic update avoids a round-trip delay on click.

## 3. Security hardening

### 3.1 Argv-only spawning

- Invariant: every git process starts through `runGitFull` with `spawn(gitBinaryPath, args, …)` and no `shell` option. A unit test asserts the spawn options.
- Git-internal shell use stays as designed by git: `GIT_SEQUENCE_EDITOR="cp '<todo>'"` quotes an `mkdtemp` path generated by the extension, never repository or webview data.

### 3.2 Option-injection guards

New module `src/git/argGuard.ts`:

| Guard | Accepts | Rejects |
| --- | --- | --- |
| `safeRev(value)` | Hex SHA (4 to 64 chars), ref names valid under `git check-ref-format` rules (checked in-process, same rules as `src/webview/lib/ui.ts`), `refs/…`, `HEAD`, `stash@{n}`, revision suffixes `^`, `~n` | Empty, leading `-`, NUL, CR, LF, whitespace, `..` inside a name, `@{` other than `stash@{n}` |
| `safeRemoteUrl(value)` | Any URL or scp-style address | Leading `-`, `ext::`, `fd::` (case-insensitive), NUL, CR, LF |
| `safeRemoteName(value)` | `check-ref-format` component rules | Leading `-`, `/`, whitespace, NUL |
| `safePath(repoRoot, value)` | Relative path, `/` separators, resolving inside `repoRoot` | Absolute paths, NUL, resolution outside `repoRoot` (`..` escape), the `.git` directory itself |

Application:

- At the op boundary: every ref, SHA, remote name, URL and path in a webview payload passes its guard before any git call or file system access. A failure rejects the op with an error toast `Invalid <field>: <value>` and an Activity Log entry.
- In git wrappers: `--end-of-options` precedes revision positionals in commands that accept it (`log`, `rev-list`, `rev-parse`, `show`, `diff`, `merge-base`, `branch`, `checkout`, `switch`, `reset`, `merge`, `rebase`, `cherry-pick`, `revert`, `tag`, `push`, `fetch`). Paths always follow `--`.
- File system writes and reads keyed by webview paths (`merge:save`, `file:open`, `file:delete`, `file:create`, `file:reveal`, `file:ignore`, `file:restore`) go through `safePath`. `merge:save` currently joins an unchecked path onto the repository root; the guard closes that write.
- Minimum Git version: 2.24 (`--end-of-options`). Conflict prediction keeps its 2.38 requirement (`merge-tree --write-tree`). On activation, `git version` below 2.24 shows an error and the client renders an empty state naming the requirement.

### 3.3 Bounded git output

- `runGitFull` retains at most `MAX_OUTPUT_BYTES = 64 MiB` of stdout plus stderr per process. Exceeding it stops the process with the escalation below and fails with `git <cmd> failed: output exceeded 64 MiB`.
- Escalation: timeout, abort or output overflow sends `SIGTERM` to the process group (POSIX) or `child.kill()` (Windows). If the child has not exited after 3 s, `SIGKILL` goes to the group. The promise settles at the first signal, as today.

### 3.4 Askpass over authenticated IPC

Credential and passphrase prompts from git and ssh open as VS Code input boxes.

Components:

| File | Role |
| --- | --- |
| `src/ipc/askpassServer.ts` | IPC server, token, request handling, prompt UI. |
| `src/ipc/askpass-main.ts` | Shim entry, bundled to `dist/askpass-main.js`. Connects, sends the prompt, prints the answer. |
| `media/askpass.sh` | Executable wrapper: `exec "$MYGIT_ASKPASS_NODE" "$MYGIT_ASKPASS_MAIN" "$@"`. Packaged with mode 0755. |

Transport:

- POSIX: unix socket `<mkdtemp dir>/askpass.sock`; directory mode 0700, socket mode 0600.
- Windows: named pipe `\\.\pipe\mygit-askpass-<32 random hex chars>`.
- The server listens before any git process that carries the askpass environment is spawned.

Authentication:

- Per extension-host session: `token = crypto.randomBytes(32).toString('hex')`.
- The token reaches the shim only through the environment variable `MYGIT_ASKPASS_TOKEN`; it never appears on argv or on disk.
- The server compares the received token with `crypto.timingSafeEqual` over equal-length buffers; a length mismatch is a rejection. A rejected connection is closed without a response.

Protocol:

- One request per connection, newline-terminated JSON: `{ "token": string, "id": string, "prompt": string }`. Maximum request size 8 KiB; a larger request closes the connection.
- Response: `{ "ok": true, "value": string }` or `{ "ok": false }`, newline-terminated.
- Connection idle timeout: 10 minutes (covers a user reading the prompt); the shim exits 1 on timeout or `ok: false`.

Environment for foreground git processes (`runGitFull` option `interactive: true`, set by user-initiated fetch, pull, push, remote branch delete, tag push and remote tag delete):

```
GIT_ASKPASS=<extension>/media/askpass.sh
SSH_ASKPASS=<extension>/media/askpass.sh
SSH_ASKPASS_REQUIRE=force
DISPLAY=${DISPLAY:-:0}           (POSIX; required by older OpenSSH)
MYGIT_ASKPASS_NODE=<process.execPath>
MYGIT_ASKPASS_MAIN=<extension>/dist/askpass-main.js
ELECTRON_RUN_AS_NODE=1
MYGIT_ASKPASS_HANDLE=<socket path or pipe name>
MYGIT_ASKPASS_TOKEN=<token>
MYGIT_ASKPASS_ID=<invocation id>
```

- `GIT_TERMINAL_PROMPT=0` stays: askpass precedes the terminal fallback in git, so prompts still reach VS Code.
- Credential helpers run first; askpass is reached only when no helper supplies a credential.
- Automatic fetch and every non-interactive invocation keep `NON_INTERACTIVE_ENV` and carry no askpass variables.

Prompt UI:

- `vscode.window.showInputBox({ title: 'mygit: Git credentials', prompt, password, ignoreFocusOut: true })`, `password` true unless the prompt matches `/username/i`.
- Escape or empty dismissal returns `ok: false`.
- Concurrent prompts queue; one input box at a time.

Timeout interaction:

- `runGitFull` registers each interactive invocation under `MYGIT_ASKPASS_ID`. While a prompt for that id is open, its `gitTimeout` timer is paused; it resumes with the remaining time after the answer.

### 3.5 Secret redaction

New module `src/git/redact.ts`:

- `redactUrl(url)`: for `http://` and `https://` URLs, removes the userinfo component entirely; removes query parameters `token`, `password`, `access_token`, `auth`, `private_token` (case-insensitive). `ssh://user@host` and scp-style `user@host:path` are returned unchanged (no secret component).
- `redactText(text)`: applies `redactUrl` to every URL-shaped substring (`[a-z][a-z0-9+.-]*://\S+`).

Applied to:

- Activity Log entries: command arguments and stderr (`setGitLogger` consumer).
- Error toasts built from `GitError` messages.
- Remote URLs in `ClientState.remotes` sent to the webview: the payload carries `fetchUrl`/`pushUrl` redacted plus a boolean `redacted`.
- Edit remote dialog: prefilled with the redacted URL; a field submitted unchanged keeps the stored URL (the extension compares against the redacted form before writing).
- "Copy remote URL": the extension reads the stored URL and writes it to the clipboard (new op `remote:copyUrl { name }`), so the full URL never travels through the webview state.

### 3.6 Payload validation

- `src/panel/messages.ts` gains a schema per op: `OP_SCHEMAS: Record<OpName, Schema>`, compiler-checked for completeness like `OP_NAMES`.
- Schema primitives: `str({ max })` (default max 4096; message bodies and merge content 16 MiB), `bool`, `int({ min, max })`, `enumOf([...])`, `arr(schema, { max })` (default max 10000), `obj({ ... })`, `optional(schema)`.
- `parseWebviewMessage` validates the payload against the op schema, drops unknown fields and returns `null` on failure. A rejected message produces an Activity Log entry `rejected message <type>: <path to failing field>`.
- Semantic guards (Section 3.2) run after structural validation, in the op handlers.
- `command` keeps its `mygit.` prefix check.

### 3.7 Hardened file writes

- `.gitignore` append (`ignoreFile`) and the commit template write (`saveCommitTemplate`) refuse a symlink target: `lstat` check, then open with `O_NOFOLLOW` where `fs.constants.O_NOFOLLOW` exists. A new `.git/gkcommittemplate.txt` is created with `O_CREAT | O_EXCL`; an existing regular file is updated in place.
- A template path configured in `commit.template` (local scope) is written only if it resolves inside the repository or its git directory; otherwise the save fails with an explanatory error.
- Temporary files for commit messages and rebase todo/messages: `mkdtemp` directories (0700) and files written with mode 0600.

### 3.8 Content Security Policy

- Nonce: `crypto.randomBytes(16).toString('base64')`.
- Policy:

```
default-src 'none';
img-src ${cspSource} https://www.gravatar.com data:;
font-src ${cspSource};
style-src ${cspSource};
script-src 'nonce-${nonce}';
```

- `'unsafe-inline'` is removed from `style-src`. Preact style props apply through CSSOM, which the policy does not block. Dynamic rules (icon theme `@font-face`, glyph classes) are inserted through a constructed `CSSStyleSheet` (`document.adoptedStyleSheets`). If a runtime check during implementation shows a blocked style path, a nonced `<style>` element replaces it; `'unsafe-inline'` is not reintroduced.
- `localResourceRoots`: `webview-dist/` plus the active icon theme's extension folder (Section 5).

### 3.9 Workspace trust

`package.json`:

```json
"capabilities": {
  "untrustedWorkspaces": { "supported": false, "description": "mygit runs the repository's git configuration and hooks." },
  "virtualWorkspaces": false
}
```

## 5. File icons from the active icon theme

### 5.1 Extension side: `src/panel/iconTheme.ts`

- Reads `workbench.iconTheme`.
  - `null`: payload `{ kind: 'none' }`; the webview renders no file or folder icons, as the Explorer does.
  - Otherwise: finds the extension in `vscode.extensions.all` whose `packageJSON.contributes.iconThemes[]` has that `id`, reads the theme JSON from `path` relative to the extension root.
  - Load failure (extension missing, JSON invalid, product icon theme id): falls back to `vscode-seti` from `vscode.theme-seti`; if that also fails, `{ kind: 'none' }`.
- Builds `IconThemePayload`:

```ts
type IconThemePayload =
  | { kind: 'none' }
  | {
      kind: 'theme';
      id: string;
      fonts: { id: string; src: { url: string; format: string }[]; weight?: string; style?: string; size?: string }[];
      defs: Record<string, { fontCharacter?: string; fontColor?: string; fontSize?: string; fontId?: string; iconUrl?: string }>;
      base: IconAssociations;
      light?: IconAssociations;
      highContrast?: IconAssociations;
      hidesExplorerArrows?: boolean;
      /** Lowercased extension (no dot) or filename → language id, from all `contributes.languages`. */
      languages: { extensions: Record<string, string>; filenames: Record<string, string> };
    };

type IconAssociations = {
  file?: string; folder?: string; folderExpanded?: string;
  fileExtensions?: Record<string, string>; fileNames?: Record<string, string>;
  folderNames?: Record<string, string>; folderNamesExpanded?: Record<string, string>;
  languageIds?: Record<string, string>;
};
```

- Font `src[].path` and definition `iconPath` values are resolved relative to the theme JSON file and converted with `webview.asWebviewUri`.
- The theme extension's root folder is added to the panel's `localResourceRoots`. Changing the theme recreates the webview options (`panel.webview.options = …`) before pushing the payload.
- Refresh triggers: `workspace.onDidChangeConfiguration('workbench.iconTheme')`, `extensions.onDidChange`. The payload is part of `ClientState` (`iconTheme`).

### 5.2 Webview side: `src/webview/lib/fileIcons.ts`

- Resolution for a file path, against the associations for the current theme kind (`highContrast` / `light` overrides merged over `base`; theme kind from `document.body.classList`: `vscode-high-contrast`, `vscode-high-contrast-light`, `vscode-light`, `vscode-dark`):
  1. `fileNames[basename.toLowerCase()]`
  2. `fileExtensions[suffix]` for each compound suffix from longest to shortest (`a.d.ts` → `d.ts`, `ts`)
  3. `languageIds[languages.filenames[basename]]`, then `languageIds[languages.extensions[ext]]` for each suffix
  4. `file`
- Folders: `folderNames` / `folderNamesExpanded[name.toLowerCase()]`, then `folder` / `folderExpanded`.
- Rendering: `<FileIcon path="…" />` and `<FolderIcon name="…" open={…} />`.
  - Font definitions: a constructed stylesheet holds one `@font-face` per theme font and one class per used definition (`.fi-<id>::before { content: "<char>"; color: <fontColor>; font-family: <fontId>; font-size: <fontSize> }`), regenerated when the payload changes.
  - SVG definitions: `<img src={iconUrl} width=16 height=16 alt="" />`.
- Results are memoised per path and payload.

### 5.3 Placement

`FileList` rows (path and tree modes, folder nodes use `FolderIcon`), "View all files" tree, diff view header, file history header, blame header, merge tool header, file pickers. Status letters (M/A/D/R) stay next to the icon.

## 6. Flow tracing

### 6.1 Behaviour

- Commit context menu (`commitMenu`): "Trace ancestors", "Trace descendants", "Trace both".
- Keyboard `T` on the graph (focus outside text inputs): cycles off → ancestors → both for the selected commit.
- Header chip in the graph header: `Tracing a1b2c3d · ancestors ▾ ×`. The dropdown switches between ancestors, descendants and both; `×` clears. `Esc` clears when no other panel is open.
- The trace origin follows the graph selection (single selection) until cleared. A multi-selection keeps the previous origin.
- Rows outside the trace set use the existing dim style (`commit-row--dim`); the origin row gets `commit-row--trace-origin` (bold summary). Graph edges between two traced rows keep full opacity; others dim.
- Interaction with other highlights: a row is dimmed when any active filter (trace, branch hover, search) excludes it. Merge marks (Section 8.3) highlight without dimming.

### 6.2 Computation

- Ancestors: existing `ancestorsOf(commitLog, sha)` in `src/webview/lib/actions.ts`, moved to `src/webview/lib/graphSets.ts` with a new `descendantsOf(commitLog, sha)` built from a reverse children map cached per `commitLog` (`WeakMap`).
- Scope: loaded commits only. When `state.hasMore` is true and the ancestor set contains the last loaded row, the chip shows `· older commits not loaded` and a "Load all" link (`graph:loadAll`).
- State: webview-local (`GraphColumn`), not persisted.

## 7. History view

### 7.1 Entry points

- Toolbar button "History" (codicon `history`), right of Search.
- Command `mygit.showHistory`, title "Show History", category mygit.
- Context menus: local branch, remote branch and tag → "Show history of <name>" (query `refs: [<ref>]`).
- Merge finder "no merge commit found" link (Section 8.4).

### 7.2 Layout

```
+---------------------------------------------------------------+
| History  Refs [main ×][+]  Author [____]  Message [____]      |
|          From [____]  To [____]  Path [____]  [Compare]  [×]  |
+---------------------------------------------------------------+
| a1b2c3d  (main) Fix parser            S. Ponzio  2026-10-07   |
| d4e5f6a  Merge branch 'feat/x'        A. Other   2026-10-06   |
| …                                     (loads on scroll)       |
+---------------------------------------------------------------+
| 1,284 commits                                                 |
+---------------------------------------------------------------+
```

- Refs: multi-select chips with a filterable picker over local branches, remote branches and tags. Empty means all refs (`--branches --remotes --tags HEAD`).
- Author, Message: case-insensitive fixed-string match.
- From, To: `YYYY-MM-DD`; invalid input marks the field and is not sent.
- Path: repository-relative path, validated by `safePath` in the extension.
- Compare toggle: replaces Refs with two single-ref pickers A and B.
- Inputs apply after a 300 ms pause; the last query persists in webview state.
- Footer: match count; `≥ N` until the count completes.
- `Esc` or `×` returns to the graph.

### 7.3 Rows and interaction

- Columns: short SHA, ref pills (same component as the graph), summary, author, date (date prefs apply).
- Click: `graph:select { shas: [sha] }`; the Commit Panel shows details whether or not the commit is loaded in the graph (`Store.select` loads detail by SHA).
- Ctrl/Cmd+click on a second row: two-commit compare (`mode: 'compare'`).
- Context menu: `commitMenu` when the commit is in the loaded graph; otherwise "Show in graph" (`graph:reveal`), "Copy commit SHA", "Create branch here", "Create tag here", "Cherry pick commit", "Revert commit".
- Keyboard: `J`/`↓`, `K`/`↑` move the selection; Enter shows in graph.

### 7.4 Compare mode

- Query `compare: { left, right }`.
- `git log --left-right --date-order --format=… --end-of-options A...B`; rows grouped under "Only in A (n)" and "Only in B (n)".
- Header action "Changed files": sets the Commit Panel to the `range` selection view with `mode: 'compare'`, `from: merge-base(A, B)`, `to: B`, files from `git diff --name-status A...B`.

### 7.5 Protocol and extension side

```ts
type LogQuery = {
  refs: string[];
  author: string;
  message: string;
  since: string;   // YYYY-MM-DD or ''
  until: string;
  path: string;
  compare: { left: string; right: string } | null;
};

type CentreView = … | {
  kind: 'log';
  query: LogQuery;
  rows: LogRow[];
  hasMore: boolean;
  loading: boolean;
  count: { value: number; done: boolean } | null;
};

type LogRow = { sha: string; parents: string[]; refs: string[]; message: string; author: string; date: string; side?: 'left' | 'right' };
```

- Ops: `view:log { query }` (open or replace query), `view:logMore` (next page).
- `src/git/log.ts`: `queryLog(repoPath, query, { offset, limit: 200, signal })` and `countLog(repoPath, query, signal)` (`rev-list --count` with the same filters). Refs go on stdin (`--stdin`), filters as `--author=`, `--grep=` with `-i -F`, `--since=`, `--until=`, then `--` and the path.
- A new query aborts in-flight `queryLog` and `countLog` processes (existing `signal` support in `runGitFull`).
- Repository refresh with the view open re-runs page one of the current query.

### 7.6 Components

`src/webview/columns/LogView.tsx` (new), `src/webview/App.tsx` (centre view routing, toolbar button), `src/panel/state.ts` (`openLog`, `logMore`), `src/panel/operations.ts`, `src/panel/messages.ts`, `src/git/log.ts` (new), `src/commands.ts`, `package.json` (command).

## 8. Merge finder

### 8.1 Entry point

Local branch and remote branch context menus: "Find merges of <A> into…".

### 8.2 Dialog: `src/webview/components/MergeFinder.tsx`

```
Find merges of feat/x into [ main                 v ]
+-------------------------------------------------------------+
| 2026-09-12  d4e5f6a  S. Ponzio  Merge branch 'feat/x'  direct        14 |
| 2026-08-30  9a8b7c6  A. Other   Merge 'release/2.1'    via release/2.1 3 |
+-------------------------------------------------------------+
| feat/x has 2 commits not yet in main                        |
| [Mark in graph]                                   [Close]   |
+-------------------------------------------------------------+
```

- Target picker: filterable list of local and remote branches, excluding A. Default: `state.targetBranch`; else the upstream's remote default branch; else `main`/`master` if present; else empty.
- Picking a target starts the search (spinner, Cancel). Changing the target cancels a running search.
- Result rows: author date, short SHA, author, subject, badge (`direct`, `via <name>`, `fast-forward`), count of A commits brought in. Click: `graph:reveal` and select the commit; the dialog stays open.
- Status lines:
  - `rev-list --count B..A` = 0: "<A> is fully merged into <B>".
  - Otherwise: "<A> has N commits not yet in <B>".
  - No results and N > 0: "No merge commit found. A squash merge or a rebase leaves no ancestry link." with a link "Search <B>'s history for '<short name of A>'" that opens the History view (`refs: [B]`, `message: <short name>`).
  - Truncated: "Stopped after 200 merges."
- `Esc` closes.

### 8.3 Mark in graph

- "Mark in graph" closes the dialog and sets graph marks: the result SHAs, in result order.
- A strip below the graph header, same component family as `FindBar`: `Merges of feat/x into main  1/3  ▲ ▼  ×`.
- Enter / ▼ next, Shift+Enter / ▲ previous; stepping to an unloaded commit uses `graph:reveal`.
- Marked rows use the search-match highlight style; other rows are not dimmed (marks highlight, they do not filter).
- Marks are independent of commit search: both can be active; the strip and the find bar stack.
- `Esc` (strip focused) or `×` clears the marks. Marks are webview-local, not persisted.

### 8.4 Algorithm: `src/git/mergeFinder.ts`

Input: `source` (A, local or remote ref), `target` (B). Output: `{ results: MergeResult[]; unmerged: number; truncated: boolean }`.

```ts
type MergeResult = {
  sha: string; date: string; author: string; subject: string;
  kind: 'direct' | 'indirect' | 'fast-forward';
  via: string | null;
  count: number | null;
};
```

Procedure (git-when-merged method):

1. `unmerged = rev-list --count --end-of-options B..A`.
2. `X = rev-parse A`; `results = []`.
3. Loop, at most 200 rounds:
   1. `X` equals B's tip: record `kind: 'fast-forward'` at `X` if `results` is empty; stop.
   2. `chain = rev-list --first-parent --ancestry-path --end-of-options X..B`. Empty: `X` is not contained in B; stop.
   3. `M` = last line of `chain`: the oldest commit on B's first-parent line that descends from `X`.
   4. `M^1` equals `X`: `X` lies on B's first-parent line. If `results` is empty, `X` is A's tip and A reached B without a merge commit: record `kind: 'fast-forward'` at `X`. Stop. A later `X` on the first-parent line is the fork point or an earlier fast-forward; the two are indistinguishable from ancestry, so neither is recorded.
   5. Otherwise `M` is a merge commit that brought `X` in. Find the parent `Pi` (i ≥ 2) with `merge-base --is-ancestor X Pi`. `kind = merge-base --is-ancestor Pi A ? 'direct' : 'indirect'`. `via` for indirect merges: parsed from the subject (`Merge branch '(.+?)'`, `Merge remote-tracking branch '(.+?)'`, `Merge pull request #\d+ from \S+?/(\S+)`), else `name-rev --name-only --no-undefined Pi` with any `~n`/`^n` suffix stripped, else `null`. `count = rev-list --count X ^M^1`. Record the result.
   6. `next = merge-base A M^1`. No merge base, or `next` equals `X`: stop. Otherwise `X = next`.
4. Rounds exhausted: `truncated = true`.
5. Results are ordered newest first.

`MergeResult.count` is `null` for `fast-forward` results.

- Every invocation passes `--end-of-options` before revisions; A and B pass `safeRev`.
- The search runs under one `AbortController`; Cancel or a new target aborts it.
- Op: `merge:find { source, target }` → state field `mergeFinder: { source; target; running; result: MergeFinderResult | null; error: string | null }` pushed to the webview.

## 9. Error handling

| Condition | Outcome |
| --- | --- |
| Payload fails schema or guard | Op dropped; Activity Log entry; toast for guard failures. |
| Git below 2.24 | Empty state with the version requirement; no repository actions. |
| Output above 64 MiB | Command fails with the overflow message; Activity Log entry. |
| Askpass server fails to listen | Interactive commands run without askpass variables (current behaviour); one warning toast per session. |
| Askpass token mismatch | Connection closed; Activity Log entry `askpass: rejected connection`. |
| Icon theme load failure | Fallback to Seti, then no icons; Activity Log entry in extended logging. |
| History query git error | View shows the git stderr (redacted) in place of rows; filters stay editable. |
| Merge finder git error | Dialog shows the error; target picker stays usable. |
